plano arquitectónico y crear cada sección cuando exista contenido real.

2. SIGNIFICADO DE LAS SECCIONES
===============================

ARCHIVOS DE LA RAÍZ

index.qmd es la portada general. acerca.qmd explica propósito y autoría.
colaboradores.qmd reconoce aportes. como-contribuir.qmd explica el flujo de
trabajo. _quarto.yml configura navegación y formatos; styles.css controla la
apariencia. Las licencias separan los derechos del contenido y del código.


CONTENIDOS/PAES

Reúne preguntas oficiales divulgadas, preguntas originales, soluciones
múltiples, distractores, errores, habilidades, técnicas, simulacros y rutas de
aprendizaje. La carpeta de una pregunta no determina toda su clasificación: una
pregunta puede relacionarse simultáneamente con varios ejes mediante tags.


CONTENIDOS/LIBRO

Es el gran libro matemático. Su jerarquía editorial es:

Parte -> Capítulo -> Sección -> Subsección -> Objeto de conocimiento

Ejemplo:

Parte II. Números
`-- Capítulo 10. Porcentajes
    |-- 10.1 Motivación
    |-- 10.2 Definición
    |-- 10.3 Representación fraccionaria
    |-- 10.4 Representación decimal
    |-- 10.5 Técnicas
    |-- 10.6 Ejemplos
    |-- 10.7 Errores frecuentes
    |-- 10.8 Problemas
    `-- 10.9 Profundización

Las secciones y subsecciones suelen vivir en el mismo QMD. No es necesario crear
una carpeta para cada una.


CONTENIDOS/UNIVERSITARIO

Contiene fundamentos, cálculo, álgebra lineal, probabilidad, estadística,
problemas de cursos y demostraciones más formales. Cada objeto universitario
debería declarar sus prerrequisitos y enlazar los fundamentos escolares.


CONTENIDOS/CURRICULUM

Describe ejes, materias, habilidades, objetivos de aprendizaje, niveles,
temarios PAES y puentes universitarios. Estos elementos pueden tener tags
propios, de modo que sean nodos reales del grafo.


REFERENCIAS

Centraliza libros, artículos, fuentes PAES, fuentes universitarias, licencias
externas y abreviaturas. bibliografia.bib permite integrar Quarto con BibLaTeX y
gestores como Zotero.


DATOS

Contiene información estructurada, no contenido pedagógico: tipos de objetos,
relaciones, tags reservados y retirados, vocabulario curricular e instituciones.


PLANTILLAS

Proporciona moldes para preguntas, capítulos, problemas, definiciones, teoremas,
técnicas, errores y fuentes. Reduce omisiones y hace consistente la escritura.


ASSETS

Almacena imágenes, TikZ, gráficos, datos, iconos y logotipos. Separar recursos
propios y externos facilita controlar licencias y atribuciones.


SCRIPTS Y FILTERS

Automatizan validaciones, backlinks, índices, rutas y transformaciones de
publicación. Los autores no deberían editar manualmente resultados generados.


DOCS

Documentación interna para autores: arquitectura, modelo de datos, convenciones
editoriales, estilo matemático, colaboración y derechos de autor.


_GENERATED

Contiene registro, catálogo, backlinks, índices, rutas y estadísticas derivados.
Nada en esta carpeta debería editarse manualmente.


.GITHUB

Administra publicación, validaciones, reserva de tags, reportes de errores y
revisión mediante Pull Requests.


3. POSIBLES MEJORAS: PROS, CONTRAS Y RECOMENDACIÓN
==================================================

3.1. CREAR CARPETAS SÓLO CUANDO EXISTA CONTENIDO

Pros:
* Evita cientos de páginas vacías.
* Reduce mantenimiento y confusión inicial.
* Permite aprender de la experiencia editorial.

Contras:
* El proyecto se verá incompleto al comienzo.
* Autores distintos pueden inventar nombres inconsistentes.

Recomendación:
Aplicarlo. Mantener este archivo como plano general.


3.2. CONFIGURACIONES DIFERENTES PARA SITIO Y LIBRO PDF

Pros:
* La web puede tener navegación libre.
* El PDF puede conservar orden lineal y capítulos estables.
* Ambas salidas comparten la misma fuente QMD.

Contras:
* Hay dos configuraciones que mantener.
* Debe definirse qué entra al libro y en qué orden.

Recomendación:
Implementarlo cuando existan tres o más capítulos completos.


3.3. ASIGNADOR Y RESERVA AUTOMÁTICA DE TAGS

Pros:
* Evita duplicados entre colaboradores.
* Impide reutilizar tags retirados.
* Reduce errores manuales.

Contras:
* Dos ramas pueden solicitar el mismo tag simultáneamente.
* Requiere diseñar un procedimiento de reserva.

Recomendación:
Alta prioridad. Inicialmente se pueden reservar tags mediante Issues de GitHub.


3.4. ESQUEMA FORMAL DEL MODELO DE DATOS

Pros:
* El modelo puede sobrevivir a Quarto.
* Facilita migraciones futuras.
* Detecta metadatos mal escritos.

Contras:
* Aumenta la complejidad inicial.
* Un esquema demasiado rígido dificulta experimentar.

Recomendación:
Definir pronto un esquema mínimo y ampliarlo gradualmente.


3.5. MATERIAS Y HABILIDADES COMO OBJETOS CON TAG

Pros:
* Permite backlinks curriculares.
* Normaliza nombres y categorías.
* Una materia puede tener explicación y prerrequisitos.

Contras:
* Aumenta el número de objetos abstractos.
* Hay que distinguir relaciones conceptuales de simples filtros.

Recomendación:
Implementarlo con un vocabulario curricular pequeño.


3.6. PROCEDENCIA Y DERECHOS POR OBJETO

Pros:
* Reduce riesgos jurídicos.
* Genera atribuciones automáticamente.
* Distingue contenido original, citado y adaptado.

Contras:
* Añade trabajo al incorporar preguntas.
* Algunas fuentes antiguas pueden estar incompletas.

Recomendación:
Prioridad máxima antes de incorporar preguntas oficiales sistemáticamente.


3.7. LICENCIAS SEPARADAS PARA CONTENIDO Y CÓDIGO

Pros:
* Aclara la reutilización.
* Facilita colaboración y atribución.
* Separa material educativo de automatizaciones.

Contras:
* Los colaboradores deben aceptar las condiciones.
* No cubre material externo cuyos derechos pertenezcan a terceros.

Recomendación:
Resolverlo antes de recibir contribuciones importantes.


3.8. PROCESO FORMAL DE REVISIÓN

Revisar cada aporte en cuatro dimensiones: matemática, pedagogía, integridad
técnica y derechos/procedencia.

Pros:
* Mejora calidad y consistencia.
* Distribuye responsabilidades.
* Conserva historial de decisiones.

Contras:
* Puede ralentizar la publicación.
* Requiere revisores con competencias diferentes.

Recomendación:
Comenzar con una lista de verificación breve.


3.9. RUTAS DE APRENDIZAJE AUTOMÁTICAS

Pros:
* Personaliza el estudio sin duplicar contenido.
* Ayuda a detectar prerrequisitos faltantes.
* Conecta diagnóstico, teoría y preguntas.

Contras:
* Un grafo correcto no siempre produce una buena secuencia pedagógica.
* Las rutas generadas necesitan revisión humana.

Recomendación:
Implementarlo cuando exista una cantidad suficiente de relaciones confiables.


3.10. BÚSQUEDA Y VISUALIZACIÓN DEL GRAFO

Pros:
* Facilita descubrir contenido.
* Muestra la naturaleza interconectada del proyecto.
* Permite detectar objetos aislados.

Contras:
* Un grafo grande puede ser confuso.
* Aumenta el peso y complejidad del sitio.
* Puede distraer si hay poco contenido.

Recomendación:
Priorizar búsqueda y filtros. Dejar el grafo como herramienta secundaria.


3.11. ESTADÍSTICAS DE APRENDIZAJE

Pros:
* Permite estudiar errores reales.
* Mejora la estimación de dificultad.
* Puede apoyar investigación educativa.

Contras:
* Implica privacidad, consentimiento y seguridad.
* GitHub Pages no debe almacenar datos sensibles.
* Muestras pequeñas pueden producir conclusiones engañosas.

Recomendación:
No implementarlo inicialmente. Tratarlo como proyecto estadístico separado.


3.12. MANTENER TAGS DE CUATRO CARACTERES

Pros:
* Son cortos y memorables.
* Existen 36^4 = 1.679.616 combinaciones posibles.
* Son cómodos para referencias y enlaces.

Contras:
* La asignación aleatoria puede producir colisiones.
* Reservar bloques reduce parte del espacio disponible.

Recomendación:
Mantener cuatro caracteres y controlar asignación y retiro.


3.13. DIFERENCIAR DOCUMENTOS Y OBJETOS

Un QMD es una unidad narrativa; un objeto con tag es una unidad semántica.

Pros:
* Los capítulos mantienen lectura fluida.
* Los objetos son referenciables individualmente.
* Evita miles de archivos diminutos.

Contras:
* Los capítulos grandes generan conflictos de edición.
* Mover objetos exige regenerar índices y enlaces.

Recomendación:
Agrupar objetos relacionados y dividir sólo cuando un archivo sea difícil de
editar o revisar.


3.14. GUÍA DE ESTILO MATEMÁTICO Y PEDAGÓGICO

Pros:
* Unifica notación, tono y terminología.
* Reduce correcciones repetitivas.
* Facilita incorporar nuevos autores.

Contras:
* Requiere mantenimiento.
* Una guía demasiado rígida puede limitar explicaciones útiles.

Recomendación:
Alta prioridad, pero comenzar con reglas breves basadas en contenido real.


3.15. ORGANIZACIÓN DE GITHUB AL CRECER EL EQUIPO

Pros:
* Permisos y roles más granulares.
* Equipos de matemática, edición, tecnología y derechos.
* Mayor continuidad institucional.

Contras:
* Añade administración.
* Puede requerir adaptar URLs y permisos.

Recomendación:
Mantener la cuenta personal al inicio y reevaluar con tres o más colaboradores
permanentes.


4. ORDEN DE IMPLEMENTACIÓN SUGERIDO
===================================

ETAPA 1. FUNDACIÓN

1. Definir tags, tipos y relaciones mínimos.
2. Resolver licencias y registro de procedencia.
3. Crear una plantilla de pregunta y una de capítulo.
4. Escribir una guía de estilo breve.
5. Publicar un capítulo y entre cinco y diez preguntas muy bien analizadas.


ETAPA 2. CONSISTENCIA

1. Crear asignador o reserva de tags.
2. Automatizar índices y validación de fuentes.
3. Formalizar el modelo de datos.
4. Incorporar revisión mediante Pull Requests.
5. Generar sitio HTML y libro PDF desde las mismas fuentes.


ETAPA 3. CRECIMIENTO

1. Ampliar M1 y comenzar M2.
2. Desarrollar las partes principales del libro.
3. Añadir contenidos universitarios conectados.
4. Generar rutas de aprendizaje.
5. Mejorar búsqueda y filtros.


ETAPA 4. INVESTIGACIÓN Y ESCALA

1. Evaluar una organización de GitHub.
2. Diseñar análisis estadísticos con criterios éticos.
3. Incorporar visualización del grafo.
4. Evaluar VPS o base de datos sólo si GitHub Pages deja de ser suficiente.


5. PRINCIPIO CENTRAL
====================

La estructura física responde a cómo los autores escriben y cómo los lectores
recorren el material. El grafo responde a qué es cada objeto y cómo se relaciona.

Una carpeta, un capítulo o una ruta pueden cambiar. El tag de un objeto publicado
no debe cambiar ni reutilizarse. Quarto es el motor de publicación; el modelo de
conocimiento pertenece al proyecto.
